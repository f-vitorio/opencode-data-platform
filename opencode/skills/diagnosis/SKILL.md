# DIAGNOSIS — Diagnóstico Estratégico

## 1. OBJETIVO

Transformar informações do cliente em um diagnóstico estruturado antes de recomendar uma solução comercial.

O diagnóstico deve evitar:

- vender uma solução inadequada;
- criar escopo desnecessário;
- precificar sem entender o problema;
- confundir sintoma com causa;
- aceitar automaticamente a solução sugerida pelo cliente.

Fluxo:

CONTEXTO
→ SINTOMA
→ PROBLEMA
→ CAUSA PROVÁVEL
→ IMPACTO
→ OPORTUNIDADE
→ SOLUÇÃO
→ ESCOPO

---

# 2. PRINCÍPIO FUNDAMENTAL

O cliente pode saber que possui um problema sem saber sua causa.

Exemplo:

Cliente:

"Preciso de uma Landing Page."

Não assumir automaticamente que o problema é a Landing Page.

Investigar:

- existe tráfego?
- existe intenção de compra?
- existe oferta?
- existe problema de conversão?
- existe tracking?
- existe processo comercial?
- existe demanda suficiente?

A solução deve ser consequência do diagnóstico.

---

# 3. SEPARAÇÃO ENTRE FATO E HIPÓTESE

Sempre separar:

### FATO

Informação comprovada ou fornecida pelo cliente.

### SINTOMA

Problema observado ou relatado.

### HIPÓTESE

Possível causa ainda não comprovada.

### DIAGNÓSTICO

Conclusão sustentada pelas informações disponíveis.

### RECOMENDAÇÃO

Ação sugerida com base no diagnóstico.

Nunca apresentar hipótese como fato.

---

# 4. ANÁLISE DO NEGÓCIO

Quando aplicável, analisar:

- produto;
- serviço;
- ticket;
- margem;
- público;
- localização;
- capacidade operacional;
- diferenciais;
- concorrência;
- processo comercial;
- aquisição atual.

Não inventar informações ausentes.

---

# 5. AQUISIÇÃO

Avaliar:

- origem dos leads;
- Google Ads;
- SEO;
- Google Business Profile;
- redes sociais;
- indicação;
- tráfego direto;
- campanhas;
- intenção de busca;
- volume de demanda.

Pergunta central:

> Existe tráfego qualificado suficiente para justificar a solução proposta?

---

# 6. CONVERSÃO

Avaliar:

- Landing Page;
- site;
- oferta;
- copy;
- CTA;
- formulário;
- WhatsApp;
- confiança;
- prova social;
- objeções;
- velocidade;
- mobile;
- tracking.

Pergunta central:

> O problema está em gerar tráfego ou transformar tráfego em oportunidade?

---

# 7. FUNIL

Quando aplicável, analisar:

TRÁFEGO
↓
VISITA
↓
LEAD
↓
ATENDIMENTO
↓
OPORTUNIDADE
↓
VENDA
↓
RETENÇÃO

Identificar onde está o principal gargalo.

Não assumir que o primeiro ponto problemático é necessariamente a causa raiz.

---

# 8. GOOGLE ADS

Quando o projeto envolver Google Ads, analisar:

- intenção;
- palavras-chave;
- correspondências;
- negativas;
- estrutura;
- anúncios;
- CTR;
- CPC;
- conversões;
- CPA;
- localização;
- orçamento;
- termos de pesquisa;
- qualidade do tráfego;
- Landing Page;
- tracking.

Separar:

PROBLEMA DE TRÁFEGO

de

PROBLEMA DE CONVERSÃO.

---

# 9. SEO

Quando envolver SEO, analisar:

- intenção de busca;
- arquitetura;
- indexação;
- conteúdo;
- entidades;
- autoridade;
- links internos;
- concorrência;
- SERP;
- CTR;
- posição;
- oportunidade comercial.

Não recomendar SEO simplesmente porque "o cliente precisa aparecer no Google".

Avaliar se a demanda orgânica é relevante para o negócio.

---

# 10. LANDING PAGES

Quando envolver Landing Page, analisar:

### Estratégia

- oferta;
- público;
- intenção;
- promessa;
- estágio de consciência.

### Copy

- clareza;
- benefício;
- diferenciação;
- prova;
- objeções;
- CTA.

### UX/UI

- hierarquia;
- navegação;
- legibilidade;
- mobile;
- confiança;
- fricção.

### CRO

- próxima ação;
- elementos de confiança;
- redução de objeções;
- alinhamento anúncio → página;
- conversão.

### Tecnologia

- performance;
- SEO técnico;
- acessibilidade;
- tracking.

A tecnologia deve servir ao objetivo comercial.

---

# 11. OFERTA

Avaliar:

- o que está sendo vendido;
- para quem;
- por quanto;
- qual benefício;
- qual diferencial;
- qual risco percebido;
- quais objeções.

Uma campanha ou Landing Page não consegue corrigir completamente uma oferta inadequada.

Quando o problema estiver na oferta, sinalizar.

---

# 12. PROBLEMA DE PREÇO

Não assumir que preço baixo significa vantagem competitiva.

Avaliar:

- posicionamento;
- percepção de valor;
- concorrência;
- margem;
- capacidade de entrega;
- público;
- ticket;
- diferenciação.

Quando a precificação estiver sendo discutida, encaminhar para a Skill:

`pricing`

A Skill `diagnosis` não deve substituir o benchmark de mercado.

---

# 13. SOLUÇÕES

Depois do diagnóstico, apresentar:

### Solução principal

A solução mais adequada.

### Alternativa

Quando existir outra abordagem razoável.

### Não recomendado

Soluções que parecem atraentes, mas não atacam o problema principal.

Exemplo:

> O cliente quer uma Landing Page, mas o principal gargalo parece ser ausência de tráfego qualificado.

Nesse caso:

**Solução principal:**
estruturação da aquisição.

**Alternativa:**
Landing Page + aquisição.

**Não recomendado:**
criar somente uma nova página sem resolver o tráfego.

---

# 14. ESCOPO

O diagnóstico deve definir somente o escopo necessário para resolver o problema identificado.

Evitar:

- adicionar serviços apenas para aumentar ticket;
- incluir funcionalidades sem necessidade;
- criar pacotes artificiais;
- transformar qualquer projeto em pacote completo.

O escopo deve nascer do problema.

---

# 15. PRIORIZAÇÃO

Classificar problemas:

### P0 — Crítico

Impede ou compromete fortemente o resultado.

### P1 — Alta prioridade

Impacta significativamente o resultado.

### P2 — Média prioridade

Pode melhorar o resultado, mas não bloqueia a operação.

### P3 — Baixa prioridade

Melhoria secundária.

Priorizar impacto sobre quantidade de tarefas.

---

# 16. OPORTUNIDADES

Depois de identificar o problema, procurar oportunidades legítimas de expansão:

- Landing Page;
- Google Ads;
- SEO;
- tracking;
- CRO;
- Google Business Profile;
- automação;
- manutenção;
- otimização contínua.

Não recomendar serviços apenas porque estão disponíveis.

A oportunidade deve estar relacionada ao problema.

---

# 17. PACOTES

Quando múltiplos serviços forem realmente necessários, considerar uma solução integrada.

Exemplo:

Landing Page
+
Tracking
+
Google Ads
+
CRO

Pode ser apresentado como um sistema de aquisição.

Mas não criar pacote apenas para aumentar o preço.

---

# 18. RESULTADO DO DIAGNÓSTICO

Produzir:

## Contexto

Resumo do negócio.

## Problema relatado

O que o cliente acredita estar errado.

## Problema diagnosticado

O que as evidências indicam.

## Causa provável

Quando ainda não houver confirmação.

## Impacto

Consequência comercial do problema.

## Gargalo principal

Onde o funil parece estar perdendo eficiência.

## Oportunidade

Onde existe potencial de melhoria.

## Solução recomendada

O que deve ser feito.

## Alternativas

Outras soluções possíveis.

## Não recomendado

O que não deveria ser feito e por quê.

## Escopo provável

Principais entregáveis necessários.

## Informações faltantes

O que ainda precisa ser descoberto.

## Próximo passo

Qual processo deve ser executado.

`pricing`

`proposals`

`negotiation`

`contracts`

`client-intake`

---

# 20. REGRA DE OURO

Não confundir:

"o cliente pediu X"

com:

"X é a melhor solução."

O trabalho estratégico da agência é descobrir a solução adequada.

A recomendação deve ser sustentada por:

PROBLEMA
+
EVIDÊNCIA
+
IMPACTO
+
OBJETIVO
=
SOLUÇÃO RECOMENDADA.

---

# 21. REGRA FINAL

O diagnóstico deve aumentar a qualidade da decisão comercial.

Nunca utilizar o diagnóstico para justificar artificialmente um preço maior.

Nunca inventar problemas para vender mais serviços.

Nunca garantir resultados.

Nunca esconder incertezas.

Quando os dados forem insuficientes, dizer claramente:

> "Ainda não temos informação suficiente para concluir isso."
