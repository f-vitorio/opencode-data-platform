# SEO-STRATEGY — Skill de Estratégia SEO

## 1. OBJETIVO

Desenvolver estratégias SEO orientadas a negócio, com base em evidências de mercado, intenção de busca, arquitetura semântica e análise competitiva.

Estratégia não é lista de palavras-chave. É um plano de ação que conecta visibilidade orgânica ao objetivo comercial.

---

## 2. PRINCÍPIO

Estratégia SEO deve responder:

- PARA QUEM estamos ranqueando?
- QUE PROBLEMA resolvemos?
- COMO o Google entende nosso conteúdo?
- QUEM são os concorrentes?
- ONDE estão as oportunidades?
- QUAL é o caminho de maior impacto?

Não produzir estratégias genéricas. Cada estratégia deve ser única para o negócio, o público e o momento.

---

## 3. SEARCH INTENT (INTENÇÃO DE BUSCA)

### 3.1 TIPOS DE INTENÇÃO

**Informational**
O usuário quer aprender, entender, descobrir.
Exemplo: "como funciona Google Ads"

**Navigational**
O usuário quer encontrar um site ou marca específica.
Exemplo: "FVS7 marketing digital"

**Commercial Investigation**
O usuário está comparando, avaliando, considerando.
Exemplo: "melhor agência de Google Ads em São Paulo"

**Transactional**
O usuário quer contratar, comprar, agendar.
Exemplo: "contratar agência de Google Ads"

### 3.2 REGRAS

- Não tentar ranquear uma página comercial para intenção informational
- Não misturar intenções na mesma página quando possível
- Criar páginas específicas para cada intenção
- Validar a intenção dominante observando a SERP atual
- A intenção pode mudar ao longo do tempo

### 3.3 COMO IDENTIFICAR A INTENÇÃO

1. Pesquisar a query no Google
2. Observar os resultados que aparecem
3. Classificar o formato dominante (artigo, produto, serviço, vídeo, lista)
4. Identificar se o Google está respondendo diretamente (featured snippet)
5. Analisar o tipo de conteúdo que ranqueia

Não inventar a intenção. Observar a SERP.

## 4. KEYWORD MAPPING

### 4.1 PROCESSO

1. Identificar as principais palavras-chave do negócio
2. Classificar por intenção
3. Classificar por volume relativo (alto/médio/baixo — sem inventar números)
4. Classificar por competitividade relativa
5. Mapear cada keyword para uma página específica
6. Verificar se já existe uma página otimizada para essa keyword
7. Identificar keywords sem página dedicada (oportunidade)
8. Identificar páginas sem keyword definida (problema)

### 4.2 REGRAS

- Cada página deve ter no máximo 1-2 keywords principais
- Keywords secundárias e termos relacionados complementam
- Não repetir a mesma keyword em múltiplas páginas (risco de canibalização)
- Quando duas páginas competem pela mesma keyword, decidir: unir ou diferenciar
- O mapeamento deve ser documentado

### 4.3 FORMATO

| Keyword | Intenção | Página | Status | Prioridade |
|---|---|---|---|---|
| google ads para clínicas | Commercial | /google-ads-clinicas | Existe | Alta |
| como funciona google ads | Informational | /blog/como-funciona-google-ads | Criar | Média |

## 5. ARQUITETURA SEMÂNTICA

### 5.1 ENTIDADES

- **Entidade principal:** O conceito central da página ou do site
- **Entidades secundárias:** Conceitos que complementam e enriquecem
- **Relações semânticas:** Como as entidades se conectam

Exemplo para uma clínica:

- Entidade principal: clínica de [especialidade]
- Entidades secundárias: tratamento, consulta, médico, exame, resultado
- Relações: clínica → oferece → tratamento; médico → realiza → consulta

### 5.2 TOPIAL AUTHORITY

O Google avalia se o site é autoridade no tópico.

Para construir topical authority:

1. Criar conteúdo que cubra o tópico de forma abrangente
2. Criar páginas que cubram subtópicos relevantes
3. Linkar internamente entre páginas do mesmo cluster
4. Demonstrar profundidade e expertise
5. Atualizar e expandir conteúdo periodicamente

### 5.3 TOPIC CLUSTERS

Estruturar o conteúdo em clusters:

- **Página principal (pillar):** Visão geral do tópico principal
- **Páginas de cluster:** Subtópicos detalhados
- **Links internos:** Conectar cluster ↔ pillar e cluster ↔ cluster

Exemplo:

```
/google-ads (pillar)
  /google-ads-para-clinicas (cluster)
  /google-ads-para-odontologia (cluster)
  /google-ads-para-estetica (cluster)
  /como-funciona-google-ads (cluster)
  /custo-google-ads (cluster)
```

### 5.4 ARQUITETURA DE INFORMAÇÃO

A estrutura do site deve ser:

- **Hierárquica:** Home → Categoria → Subcategoria → Página
- **Lógica:** O usuário deve encontrar o que procura em poucos cliques
- **Rastreável:** O Google deve conseguir acessar todas as páginas importantes
- **Escaneável:** Headings claros, conteúdo organizado, navegação intuitiva

## 6. CONTEÚDO

### 6.1 TIPOS DE PÁGINAS

**Comerciais**
- Página de serviço
- Landing page
- Página de cidade/localização
- Página de preço/orçamento
- Página de contato

**Informativas**
- Blog posts
- Artigos guia
- FAQ
- Cases de sucesso
- Glossário

### 6.2 CRITÉRIOS DE QUALIDADE

- Cobertura da intenção de busca
- Profundidade adequada ao tópico
- Clareza e legibilidade
- Diferenciação do conteúdo existente na SERP
- Atualização periódica quando relevante
- Provas, dados, exemplos
- Formatação escaneável

### 6.3 O QUE NÃO FAZER

- Copiar conteúdo de concorrentes
- Criar conteúdo genérico sem diferenciação
- Produzir conteúdo apenas para volume
- Ignorar a intenção de busca
- Criar páginas thin (pouco conteúdo relevante)

---

## 7. ENTIDADES E NLP

### 7.1 O QUE O GOOGLE ENTENDE

O Google não lê palavras-chave. Ele entende:

- Entidades (conceitos, coisas, lugares, pessoas)
- Relações entre entidades
- Contexto semântico
- Intenção por trás da consulta
- Qualidade e autoridade do conteúdo

### 7.2 COMO OTIMIZAR

- Usar a entidade principal de forma clara no título e H1
- Expandir com entidades secundárias no conteúdo
- Usar termos relacionados naturalmente
- Responder perguntas que o público faz
- Citar fontes e referências quando relevante
- Não forçar palavras-chave onde não faz sentido

### 7.3 LACUNAS DE CONTEÚDO

Identificar tópicos relevantes que não estão cobertos:

1. Listar os principais tópicos do negócio
2. Verificar se existe conteúdo para cada um
3. Identificar os mais relevantes para o público
4. Priorizar por impacto comercial e SEO

## 8. SEO LOCAL

SEO local em 2026 é uma estratégia integrada que conecta Google Business Profile, dados estruturados, reviews, conteúdo localizado e otimização para AI Overviews. Não é apenas ranquear no mapa — é ser recomendado por Google, ChatGPT, Gemini e Perplexity.

### 8.1 QUANDO APLICÁVEL

| Tipo de Negócio | Aplicável | Observação |
|-----------------|-----------|------------|
| Clínica / Consultório | ✅ Sim | Pages por especialidade + cidade |
| Odontologia | ✅ Sim | Pages por procedimento + cidade |
| Estética / Beauty | ✅ Sim | Pages por serviço + cidade |
| Escritório / Advocacia | ✅ Sim | Pages por área do direito + cidade |
| Loja física | ✅ Sim | Foco em GBP e avaliações |
| Serviços presenciais | ✅ Sim | Service-area business |
| Empresas regionais | ✅ Sim | Pages por região |
| E-commerce sem fachada | ⚠️ Parcial | Foco em SEO tradicional + local |
| Negócios nacionais | ❌ Não | SEO tradicional |

**Service-Area Business (sem fachada):**
- Usar campo "Área de atendimento" no GBP
- Criar páginas para cada cidade servida
- Não exagerar raio (Google detecta)
- Compensar com reviews e links locais

**Multi-Location Business:**
- GBP único por localização
- Página única por localização
- Schema LocalBusiness único por localização
- Organization schema como entidade pai

### 8.2 GOOGLE BUSINESS PROFILE

GBP é o ativo de maior alavancagem no SEO local. Sinais do GBP respondem por **32% do peso do Local Pack**.

#### 8.2.1 CATEGORIAS

| Ação | Regra | Exemplo |
|------|-------|---------|
| Categoria primária | Mais específica possível | "Dentist" ≠ "MedicalBusiness" |
| Categorias secundárias | Até 9, apenas serviços legítimos | "Teeth Whitening", "Emergency Dental Service" |
| Revisão | Trimestral | Verificar se há categorias melhores |

| Tipo de Negócio | Primária Correta | Primária Errada |
|-----------------|------------------|-----------------|
| Clínica | MedicalClinic | MedicalBusiness |
| Dentista | Dentist | MedicalBusiness |
| Estética | BeautySalon | HealthAndBeautyBusiness |
| Advocacia | Attorney | LegalService ≠ LocalBusiness |
| Encanador | Plumber | HomeAndConstructionBusiness |
| Oficina | AutoRepair | AutomotiveBusiness |

#### 8.2.2 DESCRIÇÃO

- **750 caracteres** (primeiros 250 visíveis antes do truncamento)
- Incluir: serviço principal + cidade + diferencial + ano de início
- Keywords naturais, sem stuffing
- Escrita como resposta direta a "o que esta empresa faz e para quem?"

| Elemento | Exemplo para Clínica |
|----------|----------------------|
| Serviço + Cidade | "Clínica de ortodontia em São Paulo" |
| Diferencial | "mais de 15 anos de experiência" |
| Credibilidade | "atendemos mais de 5.000 pacientes" |

#### 8.2.3 SERVIÇOS E PRODUTOS

- Cada serviço com nome, descrição e preço (quando aplicável)
- Alimenta filtros de busca e respostas de AI
- Keywords do serviço em cada descrição

#### 8.2.4 ATRIBUTOS

| Atributo | Impacto |
|----------|---------|
| Acessibilidade (cadeirantes) | Buscas filtradas |
| Wi-Fi | Buscas filtradas |
| Liderança feminina | Buscas filtradas |
| Formas de pagamento | Buscas filtradas |
| Estacionamento | Buscas locais |

#### 8.2.5 FOTOS

| Métrica | Impacto |
|---------|---------|
| 100+ fotos | 520% mais chamadas |
| Fotos reais | Maior confiança |
| Atualização 2-3x/semana | Sinal de atividade |
| Nome descritivo | SEO de imagens |
| Geo-tag | Sinal de localização |

**Tipos de fotos obrigatórias:**
- Logo e foto de capa
- Fachada (exterior)
- Interior
- Equipe
- Trabalhos realizados
- Produtos/serviços

#### 8.2.6 POSTS

| Tipo | Uso | Expiração |
|------|-----|-----------|
| Atualização | Novidades, dicas | 7 dias |
| Oferta | Promoções, descontos | 7 dias |
| Evento | Eventos presenciais | Até o evento |

**Regras:**
- Mínimo 1 post/semana (2 em mercados competitivos)
- CTA obrigatório em cada post
- Link para landing page específica
- Foto obrigatória

#### 8.2.7 Q&A (PERGUNTAS E RESPOSTAS)

- Semear **10-20 perguntas reais** dos clientes
- Responder da conta do negócio
- Keywords naturais nas respostas
- Atualizar conforme novas perguntas surgem

| Pergunta Comum | Exemplo de Resposta |
|----------------|---------------------|
| Preço | "Nossos tratamentos variam de R$ X a R$ Y. Agende uma avaliação gratuita." |
| Horário | "Atendemos de segunda a sexta, das 8h às 18h, e sábados das 8h às 12h." |
| Estacionamento | "Temos estacionamento gratuito no local com 20 vagas." |

#### 8.2.8 HORÁRIOS

- Horários regulares + horários especiais/feriados
- Status "Aberto" é o **5º fator de ranking mais importante**
- Atualizar sempre que houver mudança
- Negócios com serviço de emergência: horário = período de atendimento

### 8.3 PÁGINAS LOCAIS

#### 8.3.1 ESTRUTURA DE URL

| Padrão | Melhor Para | Exemplo |
|--------|-------------|---------|
| `/servico-cidade-nome` | Poucos serviços + cidades | `/ortodontia-sao-paulo` |
| `/locations/cidade-nome` | Múltiplas localizações | `/locations/sao-paulo` |

Evitar URLs profundamente aninhadas. Estruturas rasas são favorecidas.

#### 8.3.2 CONTEÚDO OBRIGATÓRIO POR PÁGINA

| Elemento | Obrigatório | Descrição |
|----------|-------------|-----------|
| Introdução única | ✅ | Não template. Contexto local genuíno. |
| Serviços na região | ✅ | O que é oferecido naquela localidade |
| Prova local | ✅ | Fotos, equipe local, eventos |
| Depoimentos locais | ✅ | Clientes daquela região |
| FAQ local | ✅ | Perguntas reais daquela região |
| Mapa | ✅ | Google Maps integrado |
| Contato local | ✅ | Telefone clique-para-chamada |
| Áreas vizinhas | ✅ | Bairros/regiões adjacentes atendidas |
| Horário | ✅ | Específico daquela unidade |
| Estacionamento/acesso | Recomendado | Informações práticas |

#### 8.3.3 REGRAS DE CONTEÚDO

- **60-70% de conteúdo único** por página
- Nunca trocar apenas a cidade em template
- Cada página deve ter algo que só pode ser escrito sobre aquela localização
- Google e AI detectam páginas doorway e as penalizam
- Meta: 10-15 cidades prioritárias com páginas completas

### 8.4 SCHEMA LOCAL E STRUCTURED DATA

Schema LocalBusiness é o **maior ROI de markup** para negócios locais. Páginas com schema válido ranqueiam 30-50% mais no Local Pack.

#### 8.4.1 SUBTIPOS POR TIPO DE NEGÓCIO

| Tipo | Schema Correto | Schema Errado |
|------|----------------|---------------|
| Restaurante | `Restaurant` | `LocalBusiness` |
| Pizzaria | `Restaurant` | `FoodEstablishment` |
| Dentista | `Dentist` | `MedicalBusiness` |
| Clínica | `MedicalClinic` | `MedicalBusiness` |
| Estética | `BeautySalon` | `HealthAndBeautyBusiness` |
| Salão | `HairSalon` | `HealthAndBeautyBusiness` |
| Advocacia | `Attorney` ou `LegalService` | `LocalBusiness` |
| Encanador | `Plumber` | `HomeAndConstructionBusiness` |
| Eletricista | `Electrician` | `HomeAndConstructionBusiness` |
| Oficina | `AutoRepair` | `AutomotiveBusiness` |
| Imobiliária | `RealEstateAgent` | `LocalBusiness` |
| Academia | `HealthClub` | `SportsActivityLocation` |
| Veterinária | `Veterinarian` | `MedicalBusiness` |

**Regra:** Sempre usar o subtipo mais específico possível.

#### 8.4.2 PROPRIEDADES

| Propriedade | Obrigatória | Descrição |
|-------------|-------------|-----------|
| `@type` | ✅ | Subtipo específico (ex: `Dentist`) |
| `name` | ✅ | Nome exato como no GBP |
| `address` | ✅ | PostalAddress completo |
| `telephone` | ✅ | Formato internacional (+55...) |
| `geo` | Recomendado | Latitude/longitude (4+ casas decimais) |
| `openingHoursSpecification` | Recomendado | Horários por dia (formato 24h) |
| `priceRange` | Recomendado | Faixa de preço |
| `image` | Recomendado | URL da imagem principal |
| `url` | Recomendado | URL canônica da página |
| `sameAs` | Recomendado | Array: GBP, Yelp, Facebook, Apple Maps |
| `aggregateRating` | Condicional | Se reviews visíveis, reviewCount >= 3 |
| `areaServed` | Subtipo específico | Para negócios de área de serviço |
| `parentOrganization` | Multi-location | Liga cada LocalBusiness ao pai |

### 8.5 SISTEMA DE REVIEWS

Reviews respondem por **20% do peso do Local Pack** e são o segundo fator mais importante.

#### 8.5.1 VELOCIDADE VS VOLUME

| Métrica | Prioridade | Observação |
|---------|------------|------------|
| Velocidade (reviews/mês) | **ALTA** | 2-5/semana > 50 de uma vez |
| Recência | **ALTA** | 73% confiam apenas nos últimos 30 dias |
| Volume total | Média | Importa, mas menos que velocidade |
| Média | ALTA | Ideal 4.5-4.8 |
| Palavras-chave nos reviews | ALTA | Cidade + serviço mencionados |

**Comparação:**
- Business A: 200 reviews de 2021 → ranqueia MENOS
- Business B: 40 reviews recentes de 2026 → ranqueia MAIS

#### 8.5.2 SISTEMA DE PEDIDO

| Momento | Método | Friction |
|---------|--------|----------|
| Após serviço concluído | SMS com link direto | Mínima |
| Na loja/escritório | Tablet disponível | Mínima |
| Via email pós-atendimento | Link + instruções | Baixa |
| QR code no local | Escaneia e avalia | Mínima |

**Regras:**
- Pedir no momento de satisfação máxima
- Link direto para formulário de review
- Nunca gating (só pedir para felizes) — viola políticas do Google
- Nunca incentivo financeiro — viola políticas do Google e FTC

#### 8.5.3 TEMPLATE DE REVIEW (SUGESTÃO AO CLIENTE)

Guiar sem forçar. Incluir:

| Elemento | Exemplo |
|----------|---------|
| Nome da empresa | "Clínica Sorriso+" |
| Serviço realizado | "tratamento ortodôntico" |
| Localização | "em São Paulo" |
| Qualidade | "profissionalismo e qualidade" |

**Exemplo de review guiado:**
> "A Clínica Sorriso+ fez meu tratamento ortodôntico em São Paulo. Profissionais competentes e atendimento excelente."

#### 8.5.4 RESPOSTA A REVIEWS

| Regra | Detalhe |
|-------|---------|
| Taxa mínima | 100% dos reviews |
| Tempo máximo | 24h (72h no máximo) |
| Conteúdo | Mencionar serviço + cidade quando natural |
| Respostas genéricas | Pouco valor, evitar |
| Review é conteúdo indexado | Resposta aparece no Google |

**Exemplo de resposta boa:**
> "Obrigado pelo feedback! Ficamos felizes que o tratamento de ortodontia em São Paulo atendeu suas expectativas. Volte sempre!"

**Exemplo de resposta ruim:**
> "Obrigado! 😊" (genérica, sem valor de SEO)

### 8.6 CONSISTÊNCIA NAP E CITAÇÕES

NAP (Name, Address, Phone) consistente responde por **6% do peso do Local Pack** e é fundamental para Entity Resolution em AI.

#### 8.6.1 PLATAFORMAS OBRIGATÓRIAS

| Plataforma | Prioridade | Alimenta |
|------------|------------|----------|
| Google Business Profile | **CRÍTICO** | Google, AI Overviews |
| Apple Maps / Apple Business Connect | **ALTA** | Siri, Apple Maps |
| Bing Places | **ALTA** | ChatGPT (usa Bing) |
| Yelp | ALTA | Bing, AI platforms |
| Facebook | MÉDIA | Múltiplas plataformas |
| Diretório da indústria | MÉDIA | Nicho específico |

#### 8.6.2 AGREGADORES DE DADOS

| Agregador | Observação |
|-----------|------------|
| Neustar | Alimenta diretórios menores |
| Foursquare | Alimenta AI platforms |
| Data Axle | Alimenta centenas de diretórios |
| Localeze | Alimenta plataforma menor |

#### 8.6.3 REGRAS DE CONSISTÊNCIA

| Erro Comum | Consequência |
|------------|--------------|
| "Rua" vs "R." | Entity confusion |
| "São Paulo" vs "S.Paulo" | Entity confusion |
| "Suite 100" vs "Sala 100" | Entity confusion |
| "+55 11 99999-0000" vs "(11) 99999-0000" | Entity confusion |
| "Ltda" vs "Ltda." | Entity confusion |

**Regra:** Caracter por caracter idêntico em todas as plataformas.

#### 8.6.4 PROCESSO DE AUDITORIA

1. Buscar "[nome do negócio] + [cidade]" no Google
2. Listar todas as plataformas onde aparece
3. Comparar NAP de cada plataforma com GBP (fonte única)
4. Corrigir inconsistências
5. Auditar **trimestralmente**
6. Priorizar plataformas autoritativas (evitar diretórios de baixa qualidade)

**5 links locais reais > 50 citações genéricas**

### 8.8 CONTEÚDO LOCAL E FRESCOR

#### 8.8.1 CITATION CLIFF

Taxas de citação caem sharp para conteúdo > 3 meses sem atualização. Atualizações incrementais mantêm sinais de frescor.

|-------------------|---------|
| < 1 mês | Alto frescor |
| 1-3 meses | Médio frescor |

## 9. ANÁLISE COMPETITIVA

### 9.1 PROCESSO

1. Identificar concorrentes orgânicos (não apenas concorrentes de negócio)
2. Observar quem ranqueia para as keywords desejadas
3. Analisar o tipo de conteúdo que ranqueia
4. Identificar padrões: formato, profundidade, estrutura
5. Identificar diferenciais: o que o concorrente não oferece
6. Identificar lacunas: o que ninguém está fazendo bem

### 9.2 O QUE OBSERVAR

- Títulos dos concorrentes
- Estrutura dos conteúdos
- Profundidade do conteúdo
- Formatos utilizados
- Presença de mídia (vídeo, imagem)
- Dados estruturados
- Links internos
- CTAs e sinais comerciais

### 9.3 DIFERENCIAÇÃO

Não copiar o concorrente. Identificar o que ele NÃO faz:

- Que perguntas não são respondidas?
- Que público está sendo ignorado?
- Que formato não está sendo utilizado?
- Que ângulo não está sendo explorado?
- Que profundidade está faltando?
