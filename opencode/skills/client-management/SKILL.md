# CLIENT MANAGEMENT / CRM

## 1. OBJETIVO

Organizar o relacionamento comercial e operacional da agência.

A Skill deve permitir acompanhar:

- leads;
- prospects;
- oportunidades;
- clientes ativos;
- clientes inativos;
- propostas;
- negociações;
- contratos;
- follow-ups;
- histórico;
- próximos passos;
- oportunidades de expansão.

O objetivo é evitar perda de oportunidades por falta de acompanhamento.

---

# 2. PRINCÍPIO

O CRM deve responder rapidamente:

1. Quem é o cliente?
2. Em que etapa ele está?
3. O que foi conversado?
4. O que foi proposto?
5. Quanto vale a oportunidade?
6. Qual é a objeção atual?
7. Quem precisa fazer a próxima ação?
8. Qual é o próximo passo?
9. Quando ele deve acontecer?
10. Existe alguma oportunidade de expansão?

Nunca inventar informações ausentes.

---

# 3. ETAPAS DO FUNIL

Usar, quando aplicável:

### LEAD

Contato identificado, mas ainda não qualificado.

### QUALIFICAÇÃO

Existe uma oportunidade potencial, mas o contexto ainda está sendo investigado.

### DIAGNÓSTICO

O problema e a necessidade estão sendo analisados.

### PROPOSTA

Uma proposta comercial foi ou está sendo preparada.

### NEGOCIAÇÃO

O cliente demonstrou interesse, mas existem objeções ou condições em discussão.

### AGUARDANDO DECISÃO

A proposta está com o cliente aguardando aprovação.

### GANHO

Cliente aceitou a contratação.

### CONTRATO

Formalização contratual em andamento ou concluída.

### ONBOARDING

Cliente contratado aguardando início ou coleta de acessos/informações.

### ATIVO

Serviço em execução.

### EXPANSÃO

Cliente ativo com oportunidade de contratar novos serviços.

### PAUSADO

Projeto ou contrato temporariamente interrompido.

### PERDIDO

Oportunidade encerrada sem contratação.

### INATIVO

Cliente que não possui serviço ativo no momento.

---

# 4. CADASTRO DO CLIENTE

Quando relevante, registrar:

## Empresa

- nome;
- nome fantasia;
- segmento;
- site;
- localização;
- canais relevantes.

## Contato

- nome;
- cargo;
- canal preferencial;
- telefone/WhatsApp quando fornecido;
- e-mail quando fornecido.

## Comercial

- origem do lead;
- serviço de interesse;
- valor estimado da oportunidade;
- etapa atual;
- probabilidade quando houver base suficiente;
- data do primeiro contato;
- último contato;
- próximo follow-up.

Não solicitar dados pessoais desnecessários.

---

# 5. OPORTUNIDADE

Cada oportunidade deve registrar, quando possível:

- cliente;
- serviço;
- problema;
- solução proposta;
- valor estimado;
- recorrência ou projeto;
- prazo;
- etapa;
- objeção;
- próximo passo;
- responsável;
- data do próximo contato.

Uma empresa pode possuir várias oportunidades.

Não misturar automaticamente oportunidades diferentes.

---

# 6. HISTÓRICO COMERCIAL

Registrar eventos importantes de forma objetiva.

Exemplo:

DATA:
20/08/2026

EVENTO:
Reunião comercial.

CONTEXTO:
Cliente demonstrou interesse em Google Ads.

PROBLEMA:
Baixo volume de leads qualificados.

SOLUÇÃO:
Google Ads Performance + Landing Page.

VALOR:
A definir.

OBJEÇÃO:
Precisa avaliar investimento.

PRÓXIMO PASSO:
Enviar proposta.

DATA DO PRÓXIMO PASSO:
A definir.

---

# 7. REGRA DE HISTÓRICO

Nunca apagar informações históricas apenas porque uma nova informação apareceu.

Quando houver mudança:

ANTIGO:
R$ 2.500

NOVO:
R$ 2.200

Registrar a alteração e, quando possível, o motivo.

O histórico deve preservar a evolução da oportunidade.

---

# 8. FOLLOW-UP

Todo follow-up deve ter:

- motivo;
- próxima ação;
- data;
- canal;
- contexto.

Evitar registros vagos como:

"Falar com cliente."

Preferir:

"Enviar mensagem pelo WhatsApp para confirmar se a proposta de Google Ads Performance foi analisada."

---

# 9. FOLLOW-UP AUTOMÁTICO

Quando uma oportunidade estiver sem próximo passo definido, sinalizar.

Quando existir um prazo de acompanhamento, registrar a data.

Quando um cliente disser:

"Vou analisar e te retorno."

Não considerar a oportunidade encerrada.

Registrar:

ETAPA:
Aguardando decisão.

PRÓXIMO PASSO:
Follow-up.

DATA:
Definir com base no contexto.

---

# 10. FOLLOW-UP SEM PRESSÃO

O follow-up deve preservar relacionamento e autoridade.

Não utilizar pressão artificial.

Evitar mensagens como:

"Última chance."

"Preciso saber hoje."

"Você vai fechar?"

A menos que exista uma razão comercial real para isso.

---

# 11. OPORTUNIDADES PERDIDAS

Quando uma oportunidade for perdida, registrar:

- motivo;
- concorrente quando informado;
- preço quando relevante;
- falta de orçamento;
- timing;
- solução inadequada;
- falta de decisão;
- outro motivo.

Não assumir o motivo.

Quando o motivo for desconhecido:

MOTIVO: não informado.

---

# 12. CLIENTES GANHOS

Quando uma oportunidade virar cliente, registrar:

- serviço contratado;
- valor;
- recorrência;
- data de início;
- prazo contratual quando existir;
- contrato;
- condições de pagamento;
- próximo passo operacional.

Depois encaminhar para:

`contracts`

e posteriormente para onboarding.

---

# 13. CLIENTES ATIVOS

Para clientes ativos, acompanhar:

- serviços contratados;
- início;
- situação atual;
- pendências;
- próximos marcos;
- oportunidades de expansão;
- risco de cancelamento quando houver evidências.

Não inventar satisfação do cliente.

---

# 14. EXPANSÃO

Para clientes ativos, procurar oportunidades legítimas de:

- Google Ads;
- Landing Page;
- SEO;
- CRO;
- Tracking;
- Google Business Profile;
- automação;
- manutenção;
- novos projetos.

Não fazer upsell artificial.

Uma oportunidade de expansão deve estar relacionada a uma necessidade real identificada.

---

# 15. CROSS-SELL

Exemplo:

Cliente possui:

Google Ads

e existe problema de conversão.

Possível oportunidade:

Landing Page + CRO.

Registrar como:

OPORTUNIDADE DE EXPANSÃO.

Não alterar automaticamente o contrato existente.

---

# 16. CLIENTES EM RISCO

Sinalizar quando houver evidências de:

- atraso recorrente;
- falta de comunicação;
- queda de resultados;
- insatisfação explícita;
- escopo indefinido;
- problemas de pagamento;
- excesso de solicitações fora do escopo.

Não classificar um cliente como "em risco" apenas por inferência fraca.

Sempre explicar o motivo da sinalização.

---

# 17. PRIORIDADE

Classificar oportunidades:

### ALTA

Alta probabilidade, alto valor ou urgência relevante.

### MÉDIA

Oportunidade real, mas sem urgência ou decisão próxima.

### BAIXA

Interesse inicial ou baixa previsibilidade.

Prioridade não deve ser baseada somente no valor financeiro.

---

# 18. VALOR DA OPORTUNIDADE

Quando possível, diferenciar:

### Valor do projeto

Valor único.

### Valor mensal

Receita recorrente mensal.

### Valor estimado do contrato

Valor mensal × duração estimada, quando houver duração conhecida.

Nunca tratar valor potencial como receita garantida.

---

# 19. INTEGRAÇÃO COM PRICING

Quando houver necessidade de definir preço:

`pricing`

A Skill de CRM não deve definir preços por conta própria.

Registrar o preço recomendado, quando fornecido pela Skill `pricing`.

Também registrar:

- preço apresentado;
- desconto;
- preço final;
- motivo da alteração.

Nunca aplicar automaticamente preço mínimo.

---

# 20. INTEGRAÇÃO COM PROPOSALS

Quando uma oportunidade chegar à etapa de proposta:

`proposals`

Registrar:

- data da proposta;
- serviço;
- valor;
- validade quando houver;
- versão;
- status.

Possíveis estados:

- rascunho;
- enviada;
- visualizada quando essa informação estiver disponível;
- em análise;
- aprovada;
- recusada;
- expirada.

Não afirmar que uma proposta foi visualizada sem evidência.

---

# 21. INTEGRAÇÃO COM NEGOTIATION

Quando houver objeção:

`negotiation`

Registrar:

- objeção;
- resposta;
- contraproposta;
- concessão;
- contrapartida;
- resultado.

Nunca registrar uma concessão como preço padrão.

---

# 22. INTEGRAÇÃO COM CONTRACTS

Quando o cliente aceitar:

`contracts`

Registrar:

- contrato solicitado;
- status;
- data;
- condições comerciais;
- pagamento inicial;
- condições especiais.

Depois da assinatura, atualizar a oportunidade para:

CONTRATO

e posteriormente:

ONBOARDING

---

# 23. ENTRADA DE NOVO LEAD

Quando receber informações de um novo potencial cliente:

1. verificar se já existe cadastro;
2. evitar duplicação;
3. registrar origem;
4. registrar serviço de interesse;
5. iniciar `client-intake` quando necessário;
6. definir próximo passo.

Não criar dados fictícios para completar cadastro.

---

# 24. DUPLICIDADE

Antes de criar uma empresa:

verificar informações disponíveis como:

- nome;
- domínio;
- e-mail;
- telefone;
- CNPJ quando fornecido.

Se houver possibilidade de duplicidade, sinalizar antes de criar outro registro.

---

# 25. COMUNICAÇÃO

Registrar somente informações comercialmente relevantes.

Não transformar o CRM em transcrição completa de todas as conversas.

Priorizar:

- decisões;
- compromissos;
- objeções;
- preços;
- mudanças de escopo;
- prazos;
- próximos passos.

---

# 26. DADOS SENSÍVEIS

Não armazenar desnecessariamente:

- senhas;
- tokens;
- chaves de API;
- dados bancários completos;
- documentos pessoais desnecessários;
- informações que não tenham finalidade comercial.

Credenciais devem ser armazenadas em mecanismos apropriados, nunca no CRM.

---

# 27. RELATÓRIO DE PIPELINE

Quando solicitado, apresentar:

## Pipeline

| Cliente | Serviço | Etapa | Valor | Prioridade | Próximo passo | Data |
|---|---|---|---:|---|---|---|

Separar:

- oportunidades abertas;
- propostas;
- negociações;
- aguardando decisão;
- ganhos;
- perdidos.

---

# 28. AGENDA DE FOLLOW-UPS

Quando solicitado, apresentar:

## Hoje

Ações que precisam acontecer hoje.

## Próximos dias

Follow-ups próximos.

## Atrasados

Oportunidades que deveriam ter sido acompanhadas e não foram.

## Sem próximo passo

Oportunidades que precisam de definição.

---

# 29. RESUMO DE CLIENTE

Quando solicitado, apresentar:

### Cliente

Nome.

### Situação

Etapa atual.

### Serviços

Contratados ou em negociação.

### Histórico

Principais acontecimentos.

### Oportunidades

Possíveis novos projetos.

### Pendências

O que precisa ser resolvido.

### Próximo passo

Ação concreta.

---

# 30. REGRAS DE DECISÃO

Nunca:

- inventar status;
- inventar follow-up;
- inventar valor;
- inventar probabilidade;
- inventar motivo de perda;
- considerar proposta aprovada sem confirmação;
- considerar contrato assinado sem evidência;
- considerar pagamento recebido sem confirmação.

Quando faltar informação:

`NÃO INFORMADO`

---

# 31. REGRA FINAL

O CRM deve funcionar como memória operacional da agência.

A cada interação importante, a pergunta é:

> "O que mudou e qual é o próximo passo?"

Registrar:

MUDANÇA
→ CONTEXTO
→ RESPONSÁVEL
→ PRÓXIMA AÇÃO
→ DATA

O objetivo não é acumular informações.

O objetivo é impedir que oportunidades, clientes, decisões e compromissos sejam esquecidos.

---

# 32. INTEGRAÇÃO COM BANCO DE DADOS

## Fonte de Verdade

O banco de dados Supabase é a fonte de verdade para todos os dados de clientes.

Arquivo de configuração: `~/.config/opencode/.env`

## Operações

### Criar cliente no banco

```bash
source ~/.config/opencode/.env
psql "$DATABASE_URL" -c "
  INSERT INTO clients (slug, company_name, segment, website, location, 
    contact_name, contact_role, contact_phone, contact_channel,
    stage, origin, service_interest, first_contact_date, priority)
  VALUES ('slug', 'Nome', 'Segmento', 'https://...', 'Localizacao',
    'Contato', 'Cargo', '(11) 99999-9999', 'WhatsApp',
    'LEAD', 'Origem', 'Servico', '2026-08-20', 'MEDIUM');
"
```

### Atualizar etapa do cliente

```bash
source ~/.config/opencode/.env
psql "$DATABASE_URL" -c "
  UPDATE clients 
  SET stage = 'PROPOSTA', updated_at = NOW()
  WHERE slug = 'slug-do-cliente';
"
```

### Registrar interação

```bash
source ~/.config/opencode/.env
psql "$DATABASE_URL" -c "
  INSERT INTO interactions (client_id, interaction_type, subject, content)
  VALUES (
    (SELECT id FROM clients WHERE slug = 'slug'),
    'REUNIAO',
    'Assunto da interacao',
    'Descricao detalhada...'
  );
"
```

### Consultar pipeline completo

```bash
source ~/.config/opencode/.env
psql "$DATABASE_URL" -c "
  SELECT company_name, stage, opportunity_value, priority, next_followup_date
  FROM clients WHERE is_active = true
  ORDER BY opportunity_value DESC NULLS LAST;
"
```

### Buscar follow-ups pendentes

```bash
source ~/.config/opencode/.env
psql "$DATABASE_URL" -c "
  SELECT company_name, contact_name, next_followup_date, next_followup_note
  FROM clients
  WHERE is_active = true AND next_followup_date IS NOT NULL
  ORDER BY next_followup_date;
"
```

## Regras

1. Sempre usar `sslmode=require` na connection string
2. Verificar duplicidade por slug antes de inserir
3. Usar soft delete (is_active = false), nunca DELETE
4. Registrar toda interação importante na tabela interactions
5. Atualizar next_followup_date quando agendar follow-up
6. Preservar histórico completo — nunca sobrescrever interações

O agente `data-platform-manager` pode ser usado para operações complexas:
- `agency db status` — dashboard do pipeline
- `agency db import [arquivo.md]` — importar de markdown
- `agency db export [slug]` — exportar para markdown
- `agency db sync` — sincronizar bidirecional
- `agency backup` — backup completo para GitHub
- `agency report pipeline` — relatório de oportunidades
- `agency report followups` — agenda de follow-ups
