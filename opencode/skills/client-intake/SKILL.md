# CLIENT INTAKE — Briefing Inteligente

## 1. OBJETIVO

Coletar e organizar as informações necessárias para compreender um cliente, oportunidade ou projeto antes de tomar decisões comerciais.

O objetivo não é fazer um questionário longo.

O objetivo é descobrir apenas as informações necessárias para tomar uma decisão melhor.

Fluxo:

CONTEXTO
→ PROBLEMA
→ OBJETIVO
→ OPORTUNIDADE
→ SOLUÇÃO
→ ESCOPO
→ INVESTIMENTO
→ PRÓXIMO PASSO

---

# 2. PRINCÍPIO

Nunca inventar informações ausentes.

Quando uma informação for importante para a decisão, perguntar.

Quando uma informação não for necessária para a tarefa atual, não perguntar apenas por completar o formulário.

O briefing deve ser adaptativo.

---

# 3. INFORMAÇÕES PRINCIPAIS

Quando aplicável, identificar:

### Empresa

- nome;
- segmento;
- localização;
- site;
- Google Business Profile;
- redes sociais quando relevantes.

### Pessoa de contato

- nome;
- cargo/função;
- autoridade de decisão;
- melhor canal de contato.

Não coletar dados pessoais desnecessários.

---

# 4. NEGÓCIO

Entender:

- o que a empresa vende;
- principais serviços/produtos;
- ticket médio quando relevante;
- margem quando o cliente puder informar;
- modelo de negócio;
- área geográfica atendida;
- capacidade de atendimento.

Não presumir ticket, margem ou capacidade.

---

# 5. OBJETIVO

Descobrir:

- o que o cliente deseja alcançar;
- por que isso é importante;
- prazo desejado;
- prioridade;
- como o cliente define sucesso.

Exemplos:

- aumentar leads;
- aumentar vendas;
- melhorar presença digital;
- reduzir custo por aquisição;
- lançar serviço;
- melhorar conversão;
- estruturar aquisição.

---

# 6. PROBLEMA

Identificar:

- problema percebido;
- problema operacional;
- problema comercial;
- gargalo de aquisição;
- gargalo de conversão;
- gargalo de atendimento;
- limitações atuais.

Diferenciar:

PROBLEMA RELATADO

de

PROBLEMA DIAGNOSTICADO.

Nunca apresentar uma hipótese como fato.

---

# 7. SITUAÇÃO ATUAL

Quando relevante, verificar:

- campanhas existentes;
- Google Ads;
- SEO;
- site;
- Landing Pages;
- Google Business Profile;
- CRM;
- tracking;
- processo comercial;
- origem dos leads;
- taxa de conversão;
- histórico de resultados.

Se dados não estiverem disponíveis, registrar:

INFORMAÇÃO NÃO DISPONÍVEL.

---

# 8. OFERTA

Entender:

- principal produto/serviço;
- preço;
- diferenciais;
- benefícios;
- público;
- objeções;
- concorrentes;
- provas disponíveis.

Não inventar diferenciais.

---

# 9. PÚBLICO

Quando necessário, identificar:

- quem compra;
- localização;
- intenção de compra;
- problema;
- necessidade;
- nível de consciência;
- fatores de decisão.

Para campanhas de busca, priorizar intenção comercial.

---

# 10. CONCORRÊNCIA

Quando relevante, descobrir:

- concorrentes principais;
- alternativas disponíveis;
- posicionamento;
- diferenciais;
- faixa de preço quando conhecida;
- percepção do cliente sobre concorrentes.

Não tratar afirmações do cliente como fatos externos sem validação.

---

# 11. ORÇAMENTO

Perguntar sobre orçamento somente quando isso ajudar a definir:

- viabilidade;
- escopo;
- investimento em mídia;
- prioridade;
- alternativas.

Não usar orçamento informado pelo cliente como única base para definir preço.

Preço deve continuar sendo analisado pela Skill `pricing`.

---

# 12. PRAZO

Identificar:

- quando o cliente gostaria de começar;
- prazo desejado;
- existência de evento ou data crítica;
- dependências do cliente;
- urgência real.

Urgência pode justificar mudança de prioridade ou escopo, mas não deve automaticamente gerar desconto.

---

# 13. AUTORIDADE DE DECISÃO

Quando relevante, descobrir:

- quem decide;
- quem influencia;
- quem aprova orçamento;
- se existe sócio;
- se existe departamento responsável.

Não presumir que a pessoa que conversa com a agência é quem toma a decisão final.

---

# 14. RESTRIÇÕES

Identificar quando relevante:

- orçamento;
- prazo;
- equipe;
- tecnologia;
- acesso às contas;
- materiais;
- aprovação;
- compliance;
- limitações operacionais.

---

# 15. PERGUNTAS ADAPTATIVAS

Não fazer todas as perguntas de uma vez.

Escolher as perguntas que faltam para a decisão atual.

### Se o usuário pedir um preço:

Priorizar:

1. serviço;
2. escopo;
3. complexidade;
4. público/mercado;
5. prazo;
6. localização quando relevante.

Depois encaminhar para:

`pricing`.

### Se pedir proposta:

Priorizar:

1. cliente;
2. problema;
3. objetivo;
4. solução;
5. escopo;
6. prazo;
7. condições.

Depois encaminhar para:

`diagnosis → pricing → proposals`.

### Se pedir negociação:

Priorizar:

1. proposta original;
2. preço;
3. objeção do cliente;
4. contexto;
5. pedido do cliente;
6. margem/escopo.

Depois encaminhar para:

`negotiation`.

### Se pedir contrato:

Priorizar:

1. partes;
2. serviço;
3. escopo;
4. preço;
5. pagamento;
6. prazo;
7. responsabilidades;
8. condições especiais.

Depois encaminhar para:

`contracts`.

---

# 16. DIAGNÓSTICO

Ao terminar a coleta, organizar:

## O que sabemos

Fatos fornecidos ou comprovados.

## O que não sabemos

Informações ausentes.

## Hipóteses

Interpretações que ainda precisam ser confirmadas.

## Riscos

Pontos que podem comprometer a solução.

## Próximo passo

A ação necessária.

---

# 17. NÃO TRANSFORMAR BRIEFING EM BUROCRACIA

Não perguntar:

- coisas irrelevantes;
- informações que já foram fornecidas;
- dados apenas para preencher campos;
- perguntas que não alteram a decisão.

Se já houver informação suficiente para executar a tarefa, executar.

---

# 18. CONTINUIDADE

Informações fornecidas durante o atendimento devem ser utilizadas nas etapas seguintes da conversa.

Não pedir novamente informações já disponíveis no contexto.

Quando uma informação importante estiver disponível em uma fonte externa ou documento validado, utilizar a fonte em vez de pedir novamente ao usuário.

---

# 19. PRIVACIDADE

Coletar somente dados necessários para a finalidade.

Evitar solicitar:

- documentos pessoais sem necessidade;
- dados bancários desnecessários;
- senhas;
- credenciais;
- informações pessoais irrelevantes.

Credenciais nunca devem ser solicitadas como parte do briefing comercial.

---

# 20. RESULTADO

Ao finalizar o briefing, produzir uma síntese objetiva:

### Cliente

Nome e contexto.

### Negócio

O que vende e para quem.

### Problema

Problema relatado e/ou diagnosticado.

### Objetivo

Resultado desejado.

### Solução provável

Solução que parece adequada, identificada como hipótese quando ainda não validada.

### Escopo provável

O que provavelmente será necessário.

### Restrições

Prazo, orçamento, equipe, tecnologia ou outras limitações.

### Informações ausentes

O que ainda precisa ser descoberto.

### Próximo passo

Qual Skill/processo deve ser acionado.

---

# 21. REGRA FINAL

O CLIENT INTAKE existe para melhorar decisões.

Não deve simplesmente coletar informações.

Seu objetivo é garantir que:

CLIENTE
+
CONTEXTO
+
PROBLEMA
+
OBJETIVO
+
ESCOPO
+
RESTRIÇÕES
=
BASE SUFICIENTE PARA DECISÃO.

Se ainda não houver informação suficiente, perguntar.

Se houver informação suficiente, não atrasar a execução.

Nunca inventar dados para completar o briefing.
